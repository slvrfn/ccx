# AGENTS.md

This file gives coding agents guidance for working on the `code-context-cli`
(`ccx`) repository. It is agent-facing documentation, not the user guide; the
user guide is `README.md` and operational details live in `docs/`.

## Project

`ccx` is a local development tool (Python 3.12, Click, hatchling) that combines
OpenCode, Claude Context semantic search, and Graphify code graphs. It is
installed as an isolated `uv` tool (`scripts/install.sh`) and exposes the
`ccx = "ccx.cli:main"` console script. Version: `0.1.3`.

## Python environment (required)

Dependencies belong to `UV_PROJECT_ENVIRONMENT`, not `/opt/venv` and not the
host repository's `.venv`. Do **not** use `uv pip --system` or install packages
into `/opt/venv` or `tests/`-adjacent `.venv` directories.

1. Initial setup: `uv sync --locked --group dev` (and `--group integration` only
   when integration tests are explicitly needed).
2. Repeated commands while dependencies are unchanged: `uv run --no-sync <cmd>`.
   Do not use `--no-sync` as a substitute for finishing an incomplete install.
3. Never clean the uv cache as a routine response to an interrupted sync.
4. The container has no GPU passthrough by default; do not rewrite PyTorch/CUDA
   requirements or select a CPU-only backend without checking with the user.

## Verification commands

- Lint + format + mypy strict + pytest + coverage + bash syntax:
  `./scripts/test.sh`
- Build wheel + sdist: `./scripts/build.sh`
- Upstream npm adapter contract check: `scripts/check-upstream.mjs`
- Integration tests (Graphify + Node + Milvus Lite, local embedding stub):
  `./scripts/test-integrations.sh` (requires `uv sync --locked --group integration`)
- Docker/model-endpoint smoke test (disposable repo, explicit opt-in):
  `CCX_RUN_DOCKER_TESTS=1 ./scripts/smoke.sh /path/to/disposable/repository`

The default pytest suite does not require Docker or model services.
`markers = ["integration: requires installed Graphify or Docker (explicit opt-in)"]`.

## Code conventions

- Ruff: `line-length = 100`, `target-version = "py312"`,
  `select = ["E", "F", "I", "UP", "B", "ANN"]`, `ignore = ["ANN401", "E501"]`.
- MyPy: `strict = true`, `python_version = "3.12"`, excludes `tests`;
  `pymilvus.*` and `graphify.*` ignore missing imports.
- Tests live in `tests/`; run with `uv run pytest`.
- Source layout: `src/ccx/` (`cli.py`, `service.py`, `config.py`, `project.py`,
  `process.py`, `docker.py`, `semantic.py`, `graph/`, `runtime/`, `watch.py`,
  `transfer.py`, `integrations.py`, `io.py`, `mcp_client.py`, `errors.py`,
  `generated.py`, `__main__.py`), `assets/` (Docker/Compose templates,
  dependency locks), `scripts/`, `docs/`.

## opencode integration

- Skill: `.opencode/skills/ccx-context/SKILL.md` (valid opencode skill format).
- Plugin: `.opencode/plugins/ccx-context.js`.
- Both are gitignored generated artifacts regenerated by `ccx open`; hand edits
  do not survive reopening.
- `graphify-out/` is local generated output (gitignored); it may be stale —
  cross-check graph results against source files.
- Semantic index and graph may be stale; cross-check against source before
  acting on either.

## Safety rules

- Use graphify for dependency, relationship, community, and impact questions;
  use claude-context semantic search for natural-language implementation
  discovery.
- Graph mutation and `clear_index` require explicit human approval.
- Do not launch graphify watch: ccx owns the one combined file watcher.
- Do not run `ccx` as root (`sudo ccx` is unsupported; the image maps the host
  user's non-root UID/GID).
- Destructive operations (`platform down`, `clear-index`, `clear-graph`,
  `import`) require confirmation unless `--yes` is supplied.
- Repository code is never removed by a ccx command; do not set
  `GRAPHIFY_OUT_DIR` to a directory containing hand-maintained assets.
- `GRAPHIFY_OUT_DIR` must stay inside the repository and cannot be the root,
  a traversal path, `.git`, `.opencode`, or a symlink path.

## Generated files

Do not expect hand edits to survive `ccx open` for: `opencode.json`,
`runtime.env`, `CONTEXT.md`, `.opencode/skills/ccx-context/SKILL.md`,
`.opencode/plugins/ccx-context.js`, and `graphify-out/`. Review generated
changes like any other project file.
