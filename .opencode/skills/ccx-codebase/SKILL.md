# ccx codebase overview

`ccx` (`code-context-cli`, version 0.1.3) is a Python 3.12 Click CLI that combines OpenCode, Claude Context semantic search, and Graphify code graphs into one local development tool. It is installed as an isolated `uv` tool and exposes the `ccx = "ccx.cli:main"` console script.

## Source layout (`src/ccx/`)

- `cli.py` — Click command parsing and presentation. Commands delegate to `Application`.
- `service.py` — `Application` orchestrates project lifecycle: `open`, `refresh`, `status`, `reindex`, watch management.
- `config.py` — `Settings` with precedence: environment > `.env` > shipped defaults. Validation for booleans, numbers, ports, uv paths, version strings.
- `project.py` — `Project` (path-derived slug, container name, collection hash) and `ProjectStore` (persisted project identity, collision detection).
- `process.py` — `Runner` protocol + `SubprocessRunner`. Only boundary allowed to launch shell commands; never `shell=True`.
- `docker.py` — `Docker` adapter: compose platform, image build/tag, container `ensure`/`exec`, interactive OpenCode launch.
- `semantic.py` — `ClaudeContext` host adapter: invoke MCP tools inside the container via `docker exec` + stdio MCP client.
- `graph/` — Graphify adapter: `backend.py` (build/status/query/clear), `output.py` (ownership marker guard), `serve.py` (read-only MCP allowlist), `status.py`.
- `runtime/` — Container-side entry points: `mcp_server.py` (FastMCP facade), `graph_build.py`, `transfer.py` (Milvus export/import), `state.py` (locks, paths, embedding identity).
- `watch.py` — Native file watcher: observer queue + debounce foreground loop, one watcher per project.
- `transfer.py` — Host-side ZIP bundle creation/validation for export/import.
- `io.py` — Atomic writes, JSON read/write, `safe_child` path traversal guard.
- `errors.py` — `CcxError` (user-facing failures).
- `integrations.py` — `ContextBackend` protocol shared by semantic/graph adapters.
- `__main__.py`, `__init__.py` — package entry.

## Conventions

- Ruff: `line-length = 100`, `target-version = "py312"`, select `["E", "F", "I", "UP", "B", "ANN"]`, ignore `["ANN401", "E501"]`.
- MyPy: `strict = true`, `python_version = "3.12"`, excludes `tests`; `pymilvus.*` and `graphify.*` ignore missing imports.
- Tests live in `tests/`; run with `uv run pytest`.
- Verification: `./scripts/test.sh` (lint + format + mypy strict + pytest + coverage + bash syntax).
- `graphify-out/` is local generated output (gitignored); may be stale — cross-check graph results against source files.
- Semantic index and graph may be stale; cross-check against source before acting on either.

## Safety rules

- Use graphify for dependency, relationship, community, and impact questions; use claude-context semantic search for natural-language implementation discovery.
- Graph mutation and `clear_index` require explicit human approval.
- Do not launch graphify watch: ccx owns the one combined file watcher.
- Do not run `ccx` as root (`sudo ccx` is unsupported).
- Destructive operations (`platform down`, `clear-index`, `clear-graph`, `import`) require confirmation unless `--yes` is supplied.
- Repository code is never removed by a ccx command; do not set `GRAPHIFY_OUT_DIR` to a directory containing hand-maintained assets.
- `GRAPHIFY_OUT_DIR` must stay inside the repository and cannot be the root, a traversal path, `.git`, `.opencode`, or a symlink path.

## Generated files (do not hand-edit; regenerated by `ccx open`)

`opencode.json`, `runtime.env`, `CONTEXT.md`, `.opencode/skills/ccx-context/SKILL.md`, `.opencode/plugins/ccx-context.js`, and `graphify-out/`.
